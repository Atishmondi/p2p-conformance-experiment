## Spec verdict: changes required

**P1 — Rebuild can publish a verdict contradicted by the displayed source trace.** `src/build_dashboard.py:45-68` derives counts from the existing conformance CSV and `src/build_dashboard.py:18-41` independently reads examples from event CSV. `src/evaluate.py:152-169` checks case IDs and scenarios, but does not verify that conformance outcomes still follow from those event rows. The README at `README.md:16-22` says the direct rebuild command updates the viewer after editing supplied run artifacts. In a temporary `--n 1` demo, I changed only S1 case `C001`'s `Vendor Invoice.qty_invoiced` to `99999`, then ran that documented builder command. It exited 0, displayed invoice delta `99999` in the trace, yet labeled the case `compliant`, with no violations; overall R3 violating count stayed at 2. This violates the source-derived, truthful dashboard and dataset-edit contract. Recompute v2 conformance from the changed event logs before building, or reject changed logs whose conformance results no longer match; add a regression test that mutates an event quantity and checks the verdict. If the command requires users to regenerate conformance first, the documented one-step rebuild path must perform or explicitly require that step. Existing test `tests/test_portability.py:83-108` mutates the conformance CSV instead, so it misses this mismatch.

**P2 — Copied pilot document contains a broken source link.** `src/build_dashboard.py:79-88` copies `erp-pilot.md` and `event-contract.md` but no `examples/` fixture. The copied document at `webpage/docs/erp-pilot.md:3` links to `../examples/erp-recorded-events.csv`; resolving that target in the checked-in bundle reports missing. The same defect is produced in a standalone run. Copy the small synthetic fixture to the matching relative location, or alter the bundled document to a resolvable link. Extend the portability assertion to resolve links inside bundled documents, not only the top-level page and provenance artifacts.

The other Task 4 requirements reviewed are substantially met: the checked-in bundle has schema `2.0`, 120/60 lab cases, field total 251,734, and five provenance entries whose copied bytes match their displayed SHA-256; source paths in `data.json` are relative. The field summary source was sanitized to `source_xes: BPI_Challenge_2019.xes`; no raw XES is bundled. UI rule and case denominators distinguish unknown from evaluated, field strata retain applicable counts, and lab/field/ERP claims are separated. The README, business case, claim map, supersession notices, portable verifier, and CI are present. These positives do not resolve the two defects above.
